Kniha jázd on the PC: Miesta (current state)

The place book at /miesta, with the map dialog that sets a position, as it works on main. The example data is invented. The UI text is Slovak, as in the app. The notes under each frame say what the screen does.

The source is docs/mockups/miesta.html in the repo. Its git history shows when the page changed.

An orange dashed box with the tag "Návrh (task NN)" marks a proposal that is not built yet. This page has no open proposal.

  • The page loads the list once, at mount, with list_places. The list holds every place of the book. The vehicle and the year pickers do not filter it.
  • The backend sorts the list: the places with no position first, then the most used, then the name. The page does not sort again (ADR-008).
  • "{n}/{total} umiestnených": n counts the places that have a latitude and a longitude.
  • The use count is the number of trip endpoints (origin or destination) that point at the place, for all vehicles and all years. A trip from a place to the same place counts 2.
  • The use text follows the Slovak plural: "1 výskyt", "2 výskyty" to "4 výskyty", "0 výskytov" and "5 výskytov" or more.
  • ⚠ shows when the place has no position (tooltip "Treba doplniť polohu"). This occurs for a place that the database migration made from the old trip text. The coordinates then show "-".
  • The coordinates are latitude, longitude, rounded to 3 decimals (about 100 m).
  • The house is the home mark. It is filled for the home place, and pale for the others. The tooltip is "Zrušiť označenie domova" on the home place and "Označiť ako domov" on the others.
  • A click on the house calls set_home_place with the place id, or with null on the home place. Only one place can be home, so a new mark removes the old one.
  • The home mark is the "home" of the journey grouping (BIZ-026). The MCP tool list_journeys reads it, and it returns an error when no place is home.
  • "Upraviť" opens the map dialog (frame 3). "Premenovať" opens the rename input in the row (frame 2).
  • "Zmazať" is disabled when a trip uses the place. Its tooltip is then "Miesto je použité {n}-krát.". Else it opens the confirm (frame 6).
  • "Hľadať..." shows only when the book has a place. It filters in the browser on each key, with no RPC call.
  • The filter lowercases and trims the query. A row matches when the query is in the lowercased name or in normalisedName.
  • normalisedName comes from the backend fold places::normalise: lowercase, no diacritics, one space. So "Kosice" finds "Košice". "košice" finds it through the name.

  • Add. "Pridať miesto" changes to the input "Názov miesta" (placeholder), "Ďalej" and "Zrušiť". "Ďalej" is disabled while the input is blank.
  • Enter does the same as "Ďalej". Escape does the same as "Zrušiť".
  • "Ďalej" writes nothing. It opens the map dialog (frame 3) with the typed name. A new place always gets a name and a position together.
  • "Uložiť miesto" in the dialog calls create_place with the name, the latitude, the longitude and the source. On success the add bar closes and the list loads again.
  • If the user closes the dialog, nothing is saved. The add bar stays open with the typed name.
  • Rename. "Premenovať" puts an input with the current name in place of the name. "Uložiť názov" is disabled while the input is blank. Enter saves, Escape cancels.
  • Only one row can be in rename at a time. The buttons on the right of the row stay active.
  • "Uložiť názov" calls rename_place. Trips store the place id, not the text (ADR-055), so the new name shows on every trip, also in past years.
  • The backend joins the extra spaces of a name. It refuses a name whose fold (places::normalise) another place already has: "Miesto s týmto názvom už existuje: {name}". The app does not merge two places.
  • The same rule applies to a new place. A blank name returns "Miesto musí mať názov". These texts come from places_cmd.rs, not from i18n.

  • "Upraviť" (an existing place) or "Ďalej" (a new place) opens the dialog. The title is "Umiestniť na mape", with the place name under it.
  • The search input (placeholder "Zadajte adresu alebo názov miesta") starts with the place name. The user can change the query.
  • Only "Hľadať" or Enter starts a search, never a key press: Nominatim allows one request per second. The RPC is geocode_place. It writes nothing.
  • The backend asks the public Nominatim with limit=5 and accept-language=sk, and with no country filter (ADR-035). So the list has up to 5 results, best first.
  • A result text is the address of the geocoder. A click on a result sets the pin there, zooms the map to level 15, and marks the result green. The page keeps only the coordinate, not the result text.
  • The map is Leaflet with OpenStreetMap tiles. A place with a position opens at its pin, zoom 15. A place with no position opens on Slovakia, zoom 7, with no pin.
  • A click on the map sets the pin. The pin is draggable. A click or a drag sets the source to manual; a result sets it to geocoder.
  • The coordinates under the map show the pending pin to 3 decimals, or a long dash (U+2014, the literal in PlaceModal.svelte:205) with no pin. Nothing is saved before "Uložiť miesto".
  • "Uložiť miesto" is disabled with no pin. It calls set_place_position (existing place) or create_place (new place), then closes the dialog and loads the list again.
  • "Zrušiť", the × button, a click on the dark background and Escape close the dialog with no write.

  • Before the first search, the dialog shows no status line. With no pin, "Uložiť miesto" is disabled.
  • While a search runs, the button reads "Hľadám..." and is disabled. The status line under it also reads "Hľadám...".
  • An empty answer shows "Nič sa nenašlo. Umiestnite špendlík na mape ručne." The user then clicks the map to set the pin.
  • Any error (network, Nominatim rate limit, block) shows "Vyhľadávanie zlyhalo. Skúste to znova." in red. The old results go away, so no result of an old query can be saved.
  • A new search replaces the results. The pin stays where it is until the user picks a result or moves the pin.
  • The integration tests set KNIHA_JAZD_MOCK_GEOCODER_DIR: the backend then reads the answers from files and uses no network.

  • The confirm opens only for a place with 0 uses. "Zrušiť", Escape or a click on the background closes it.
  • "Zmazať" calls delete_place. The backend counts the trips again in the same transaction. It also deletes the saved routes of the place, because a route with no trip does not show anywhere.
  • If a trip uses the place at that time, the backend refuses: "Miesto používa {n} jázd, nedá sa zmazať" (backend text in places_cmd.rs).
  • The toasts show at the top right. A success toast stays 4 s, an error toast 6 s.
  • Each write has its error toast with the backend message: "Nepodarilo sa uložiť miesto: ...", "Nepodarilo sa premenovať miesto: ...", "Nepodarilo sa zmazať miesto: ...", "Domov sa nepodarilo nastaviť: ...".
  • The page builds the message with String(error), so the text carries the prefix "Error: " (see the open points).

8. Jazdy editor: a trip accepts only a place from the book

Miesto "Klient Nitra" neexistuje. Pridajte ho na karte Miesta.
  • A trip stores the ids of its two places (ADR-055, BIZ-025). The save in the Jazdy editor looks up each typed name in the book.
  • The lookup uses the same fold: find_place calls places::normalise. So "kancelaria" finds "Kancelária", and the trip stores the book spelling.
  • If a name is not in the book, the save stops and the row shows "Miesto "{name}" neexistuje." with the link "Pridajte ho na karte Miesta.".
  • The link opens /miesta in a new tab, so the open row keeps its data.
  • If the lookup itself fails, the row shows "Miesto sa nepodarilo overiť. Skúste to znova."
  • Outside this page, Fuelio "+ Nové miesto tu" and the phone page /m/nova also create places, with the same name rule.

Open points (from the code, not fixed)

  • The error toasts show "Error: " before the backend message. apiCall throws new Error(text) (src/lib/api-adapter.ts:16), and the page formats it with String(error) (src/routes/miesta/+page.svelte:106, :147, :159, :173).
  • A failed list_places shows the empty-book text, not an error. The catch only logs to the console (src/routes/miesta/+page.svelte:62-64).
  • The name sort is the byte order of the string, not the Slovak order. A name that starts with a letter with a diacritic ("Čerpacia ...", "Žilina") sorts after "Z" in its group (src-tauri/core/src/commands_internal/places_cmd.rs:27).
  • The list shows "-" for no position, but the dialog shows a long dash, U+2014 (src/routes/miesta/+page.svelte:313, src/lib/components/PlaceModal.svelte:205).
  • "Hľadám..." shows twice while a search runs: on the button and in the status line (src/lib/components/PlaceModal.svelte:251, :256).
  • The i18n key places.unplaced ("Neumiestnené") has no use in src/ (src/lib/i18n/sk/index.ts:792).
