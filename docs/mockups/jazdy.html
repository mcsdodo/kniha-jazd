Kniha jázd on the PC: Jazdy (current state)

The trip logbook at / and the app shell (header, nav, pickers), as they work on main. The example data is invented. The UI text is Slovak, as in the app. The notes under each frame say what the screen does.

The source is docs/mockups/jazdy.html in the repo. Its git history shows when the page changed.

An orange dashed box with the tag "Návrh (task NN)" marks a proposal that is not built yet. This page has no open proposal.

  • The title "Kniha Jázd" opens the logbook. The active page has a lighter background in the nav.
  • The red count next to "Doklady" is the number of Paperless fuel invoices with no trip (tooltip "Nepriradené doklady"). Other-cost invoices do not count. It refreshes every 5 min and after an assign. It hides at 0 and on an error (count_unlinked_paperless_fuel_invoices).
  • "Fuelio" shows only when the three DROPBOX_* env vars are set (is_fuelio_available).
  • Below 640 px the nav also shows "Mobilná verzia", a link to /m.
  • "Vozidlo:" lists "name (plate)". With no vehicle it shows "-- Žiadne vozidlá --". A change sets the active vehicle and resets the year to the current year.
  • "Rok:" shows only with an active vehicle. It lists the current year and each year with trips, newest first. A year with no data jumps to the newest year with data.
  • The yellow banner shows only in read-only mode: the database has migrations that this build does not know. The banner has no buttons.
  • The header has no theme control. The theme comes from the settings page.

  • "Jazdy (N)" counts the trips of the year. The data comes from get_trip_grid_data: the backend computes each rate, warning and fuel remaining (ADR-008).
  • "Nový záznam" opens an editor row at the top (frame 8). It is disabled while a row is open ("Najprv dokončite otvorený záznam").
  • "+1 deň" / "Dnes" sets the date that a new row gets: the day after the last trip, or today ("Predvyplnený dátum pre nový záznam").
  • The eye button opens the column menu (frame 5). Its badge counts the hidden columns.
  • A click on "#" flips the sort: ▼ is newest first, ▲ is oldest first.
  • The legend shows only the items that occur, each with its count. 💡 is the fill-up that brings the open period to a safe rate.
  • Warning icons: ⚠ in "PHM (L)" or "Iné €" is a missing invoice (also without Paperless set). ⚠ on "Začiatok" / "Koniec" is an invoice time outside the trip, or the same date and time as another trip. ⚠ on "ODO" is an odometer that does not match the km. * is a partial fill-up.
  • An orange row is a fill-up period over 120 % of the TP rate. "~" in "l/100km" is a rate estimated from TP (the period is still open, "Odhad podľa TP").
  • "30.09. -" is a month-end row: only the ODO and the fuel remaining. "Prvý záznam" holds the odometer and the fuel at the start of the year (carried over from last year).
  • Row icons, from left: "Vložiť záznam nad", "Kopírovať záznam", "Kopírovať opačnú trasu", the map pin ("Pridať mapu trasy", or filled: "Zobraziť mapu trasy", opens /mapa?trip= in a new tab), "Odstrániť záznam".
  • A double-click on a row opens the editor (frame 7).
  • With no trips the grid says "Žiadne záznamy. Kliknite na "Nový záznam" pre pridanie jazdy."

  • One row is open at a time. The icons of the other rows are disabled while a row is open.
  • "Začiatok" and "Koniec" take "DD.MM HH:MM". An invalid value gets a red border. With "Zobraziť výber dátumu a času" set, a calendar button "Vybrať dátum a čas" shows too.
  • "Odkiaľ", "Kam" and "Účel" show a filtered list of the known values. A place must exist in the place book (find_place). An unknown name shows the red line "Miesto ... neexistuje." with a link to the Miesta page.
  • A known route fills the km. A typed km moves the ODO. On an existing row a typed ODO sets the km (ODO minus the odometer before). An ODO below the row before shows the error toast "Tachometer je nižší ako predchádzajúci záznam, vzdialenosť by bola záporná".
  • On a new row the ODO comes from the chain of the trips before it, not from a typed value (intended: create_trip_cascade takes no odometer).
  • "Plná" shows once liters are typed. BEV / PHEV rows have "Plné nabitie" next to the kWh.
  • The values with "~" are a live preview from the backend (preview_trip_calculation). "(+7%)" is the margin over TP: green under 20 %, red over 20 %.
  • ✦ "Automatické doplnenie" fills "PHM (L)" with the suggested liters for the open period, inside the legal limit and the tank (BIZ-003, BIZ-028), and sets "Plná". ✓ (or Enter) saves. ✕ (or Esc) cancels.

  • The dialog opens only when a save, an insert or a delete moves the odometer of later trips. The backend computes the plan in a dry run.
  • The first line depends on the action: "Táto zmena posunie ..." (edit), "Nová jazda posunie ..." (insert), "Zmazanie posunie ..." (delete).

  • The backend renders this HTML page (export_html, template in src-tauri/core/src/export.rs). It is the legal document of the year.
  • The header has the company and IČO from "Nastavenia spoločnosti", and the vehicle. A BEV shows "Batéria:" and "Základ. spotreba:" in place of the tank and TP.
  • With "Tlačiť knihu jázd vždy v jednotnom tvare" set, the export is always oldest first and has all columns. It ignores the sort and the hidden columns of the grid.
  • The footer has the year totals and "Odchýlka od TP". The stored route maps print as attachment pages after the table, each with the heading "Príloha č. N — záznam č. R" and the OpenStreetMap credit.
  • "Export do Excelu" writes the same header, rows and totals to sheet "Kniha jázd", and the route maps to sheet "Prílohy". It has exact values, shown rounded, and no formulas. Not drawn.

Open points (from the code, not fixed)

  • The vehicle card always shows "Objem nádrže" and "Spotreba (TP)", also for a BEV, where both are empty (src/routes/+page.svelte:274-281).
  • ✦ "Automatické doplnenie" shows in the editor for each vehicle type. For a BEV it fills a fuel field that the grid does not show (src/lib/components/TripRow.svelte:952).
  • The page has no read-only handling: the grid, the editor and "Nový záznam" stay active. A dry run skips the read-only guard (src-tauri/core/src/commands_internal/trips.rs:934), so the cascade dialog can open, and the write then fails with a generic toast.
  • Unused i18n keys of the old compensation suggestion: compensation.suggestionTitle, compensation.addTrip, compensation.searchingSuggestion.
