Kniha jázd on the phone: current state

Twelve phone screens under /m, as they work on main. The example data is invented. The UI text is Slovak, as in the app. The notes under each screen say what the screen does.

The source is docs/mockups/mobil.html in the repo. Its git history shows when the page changed.

An orange dashed box with the tag "Návrh (task NN)" marks a proposal that is not built yet. This page has no open proposal.

  • The chips list the alternatives, fastest first, in the order the backend sends them, at most 3. With one route there are no chips and the line says "Podľa trasy: ...". See screen 9 for a tap on route 2.

Miesto je použité 4-krát.
  • The search box starts with the place name. "Hľadať" asks the geocoder of the PC Miesta page (geocode_place). A tap on a result moves the pin there and zooms in.
  • Nothing is saved until "Uložiť miesto". A search result only moves the pin (ADR-032). The stored name stays the name in the field, never the address (ADR-034).
  • No result: "Nič sa nenašlo. Umiestnite špendlík na mape ručne." A failed search: "Vyhľadávanie zlyhalo. Skúste to znova."
  • "Moja poloha" moves the pin to the GPS point of the phone, as in the manual add page. The GPS errors of that page apply here too. While the GPS request runs, "Uložiť miesto" is disabled. A GPS answer that comes after a search pick or a map tap is ignored.
  • "Uložiť miesto" writes only what changed: the name (rename_place), the pin (set_place_position), the home mark (set_home_place). Then the list opens with the toast "Miesto uložené". A name that another place has fails with the backend message.
  • Under the map: after a tap, a drag or "Moja poloha", the line shows "Poloha: {lat}, {lon} (ručne)" with 5 decimals (screen 12). Otherwise it shows "Ťuknite na mapu alebo posuňte špendlík."
  • "Zmazať" works only for a place that no trip uses. Otherwise it is disabled, and the line under it gives the count. It asks "Zmazať miesto?" first.
