Kniha jázd on the PC: Nastavenia (current state)

The settings page at /settings and its dialogs, as they work on main. The example data is invented. The UI text is Slovak, as in the app. The notes under each frame say what the screen does.

The source is docs/mockups/nastavenia.html in the repo. Its git history shows when the page changed.

An orange dashed box with the tag "Návrh (task NN)" marks a proposal that is not built yet. This page has no open proposal.

  • The effect of each checkbox is on the Jazdy page: the calendar button in the row editor, the time fill of a new row, and the form of "Export pre tlač" and "Export do Excelu".

  • The eye button of the HA token and of the Paperless token opens this prompt. It asks on each reveal. The page keeps no PIN.
  • "Zobraziť" or Enter sends reveal_secret with the field and the PIN. A correct PIN closes the prompt and shows the token as text in the field. The eye icon changes to "Skryť".
  • The PIN is the env var KNIHA_JAZD_REVEAL_PIN on the server. Without it, no reveal is possible. The prompt then shows "Revealing secrets is disabled: KNIHA_JAZD_REVEAL_PIN is not set on the server."

  • "Zrušiť" closes the prompt. A click on the dark area or Esc does not close it.
  • A revealed token goes away when the page closes.

Open points (from the code, not fixed)

  • "Pridať vozidlo" drops the three HA sensor fields. The dialog shows them, but createVehicle takes no sensor arguments (src/routes/settings/+page.svelte:633-645, src/lib/api.ts:15-41), and the backend sets them empty (src-tauri/core/src/commands_internal/vehicles.rs:81-83). Only an edit saves them.
  • A new vehicle is saved as active, and the other vehicles stay active (src-tauri/core/src/commands_internal/vehicles.rs:78). After an add, the list can show "Aktívne" on two rows.
  • A clear of the HA or Paperless URL or token does not clear it. The page sends an empty value as null, which the backend reads as "keep" (src/routes/settings/+page.svelte:294-295, :355-356; src-tauri/core/src/commands_internal/integrations.rs:234-242, :334-341). The toast still says saved.
  • After a save of the HA URL alone, the page sets "no token" (haHasToken = !!haApiToken, src/routes/settings/+page.svelte:299). The status line hides, the eye button is disabled, and the "********" placeholder goes away until a reload. The vehicle dialog also loses the three sensor fields (haConfigured, :1516). Paperless reads the value back and has no such problem (:361-362).
  • "Nastaviť ako aktívne" and "Odstrániť" refresh only the vehicle list, not the active vehicle (src/routes/settings/+page.svelte:673-705). The header select shows the old vehicle until a reload (src/routes/+layout.svelte:163).
  • "Automatické čistenie" never runs on its own. Nothing reads the setting except this page (src-tauri/core/src/commands_internal/backup.rs:308). It counts only pre-update backups (backup.rs:151-166), and nothing creates one now: createBackupWithType has no caller (src/lib/api.ts:270).
  • The automatic backups of this build are the pre-migration backups at start (src-tauri/core/src/db.rs:79-82). They get no badge (src/routes/settings/+page.svelte:1455), and the cleanup does not count them, so they stay until a manual delete.
  • "Účel kompenzačnej jazdy" has no effect. Only the settings load and save use buffer_trip_purpose. No suggestion or export code reads it. The hint "Tento účel sa použije pri plánovaní jázd..." is out of date (src/routes/settings/+page.svelte:1373-1386).
  • The page has no read-only handling: no control is disabled. The guarded writes (company, vehicles, HA, Paperless, retention, restore and delete of a backup) fail with an error toast (check_read_only!). "Zálohovať" works on purpose (backup.rs:181-184). The theme, the three preference checkboxes and "Vyčistiť teraz" still write (src-tauri/core/src/commands_internal/settings_cmd.rs:56, :127, :144, :160; backup.rs:281).
  • The preference handlers have no error handling. A failed save shows nothing and the control keeps the new state (src/routes/settings/+page.svelte:441-462). The retention errors show the raw backend text in the toast (:813, :827).
  • After the first save of a Paperless URL and token, "Vlastné polia" shows with no selects until a click on "Obnoviť zoznam polí". The save does not read the fields (src/routes/settings/+page.svelte:343-369, :1173).
  • The PIN prompt shows the backend errors in English ("Incorrect PIN.") in the Slovak UI (src-tauri/core/src/commands_internal/reveal.rs:82-90, src/routes/settings/+page.svelte:88). Its buttons have no page style: no CSS rule for .button-secondary or the bare submit button (:1500-1505).
  • Some colours are fixed values that do not change in dark mode: the status line, the HA ODO badge and the "pred {version}" badge. The page uses undefined variables with light fallbacks (--color-success-bg, --color-error-bg, --accent-light; src/routes/settings/+page.svelte:1668-1671, :1880-1886, :2169-2177). The env badge and the disabled inputs use --bg-secondary and --border-color, which src/lib/theme.css does not define (:2093-2095, :2105).
  • Unused i18n keys of this page (src/lib/i18n/sk/index.ts): settings.saveSettings (:284), settings.revealWindows / revealMac / revealLinux (:292-294), all 17 settings.dbLocation* keys (:323-339), toast.errorMoveDatabase / errorResetDatabase (:434-435), homeAssistant.tokenNotSet, notConfigured, configureFirst, connectionError (:897, :910-911, :916), paperless.status.idle (:976), and all update.* keys except update.currentVersion and update.showChangelog (:930-962).
